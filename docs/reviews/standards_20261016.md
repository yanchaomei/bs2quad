## 已闭环问题

1. **缓冲输出失败仍返回成功。** 原实现只在流析构前检查状态，小型 JSON 和 CSV 尾部的写入失败可能未被发现。`include/CheckedOutput.h` 的 `FinishOutput` 现明确执行 flush、close 并检查状态；CLI 报告、证据逐例 CSV/输入清单/JSON、CAD 查询 CSV/原始 CSV/JSON 均调用该方法。Linux 的 `OutputFailureContracts` 使用 `/dev/full` 验证失败退出，最终 Release 的 CTest 记录显示该组通过。
2. **公开布尔性能接口把空结果计为完成。** `AccuracyValidator::BenchmarkBoolean` 现要求结果除有效且非空句柄外，还至少含面、边或顶点；公开接口回归验证空布尔结果不得发布已完成的加速比。该修复与 CAD 基准已有的有效、非空操作结果门槛共同避免空操作假收益。
3. **未执行几何比较却报告零误差。** CAD 基准的 setup 异常分支现将 `maxError` 设为无穷，在 JSON 中输出 `null`，并保留 `valid:false` 及失败原因，与原始失败记录一致。
4. **包裹曲面的接口处理不一致。** 验证器新增 `BSplineSupport`，解开 `Geom_RectangularTrimmedSurface` 后读取 B 样条基面。此前仅记录为待核实候选问题；本次确认源码已补齐一致性处理，不把此前候选描述为已实测缺陷。
5. **验证脚本可能出现空测试或混用旧回执。** `scripts/verify.sh` 强制开启 `BUILD_TESTING`、要求 CTest 至少发现测试，拒绝复用非空证据目录，并分别保留正确性、兼容性、时延与 CAD 性能目标状态。
